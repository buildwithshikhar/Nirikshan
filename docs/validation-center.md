# Validation Center API

Read-only views over the committed `make validate` results, plus a sandboxed re-run. Every number is measured on **reference test data** generated by Nirikshan's own harness, not captured from a physical DVR. Parsers built from a published layout and tested on images generated from that same layout are a **circular check**, not independent validation. No vendor is above Tier B and nothing has been validated on a real device. This statement (`basis`) is attached to **every** metric object the API returns (any dict with `rate` or `count`); a test walks each response to check it.

## Source file

`$NIRIKSHAN_VALIDATION_RESULTS` if set, otherwise `<repo root>/docs/validation/results.json` (repo root = two levels above the `app` package). When the file is missing or is not a result file, every read endpoint answers `{"available": false, "reason": ..., "path": ...}`; nothing is substituted. Container images that do not ship `docs/` must set the variable or will report unavailable.

On load, the results digest is recomputed with `app.validation.run.digest` (timings excluded) and reported as `digest_verified`; an edited file shows `false`.

## Endpoints

| Method | Path | Content |
|---|---|---|
| GET | `/api/validation/summary` | origin headline, disclaimers, seed, trials, engines, tool and ffmpeg versions, file SHA-256, digest check |
| GET | `/api/validation/scorecards` | per vendor (Generic carver, Dahua, Hikvision, Honeywell): tier (from the parser classes), every scenario per engine with clip recall, clip precision, frame recall, byte-exact, decode-ok; pooled recall/precision (sum of k and n, labelled descriptive only) |
| GET | `/api/validation/regression` | `app/validation/thresholds.json` re-checked with `app.validation.thresholds.check` (all scenarios required for a full run), per-rule observed value and pass/fail, and whether it matches the violations stored in the file |
| GET | `/api/validation/false-rates` | negative scenarios (clips emitted, decodable clips = false accepts, flagged failures), fragment-reassembler false/true accept (measured with the reassembler on; it is off by default), false-positive clips per positive scenario ((carved − true positives) / carved) and mixed clips |
| GET | `/api/validation/crosscheck` | parser-vs-generic disagreement kinds per scenario and per vendor, benign kinds, non-benign disagreement-image rate |
| POST | `/api/validation/reruns` | start a re-run (examiner required) |
| GET | `/api/validation/reruns`, `/api/validation/reruns/{id}` | status, command, digests, comparison |

## Re-run

Body: `{trials?, seed?, export=true, scenarios?}`; seed and trials default to the baseline's. Scenario ids are checked against `app.validation.scenarios.SCENARIOS`.

The existing job system cannot hold it (its rows need a case and evidence item), so the re-run is a **single subprocess at a time** (409 while one runs):

- argument list built from validated values, no shell: `python -m app.validation.run --seed S --trials N --out <tmp> [--no-export] [--only ids]`, working directory `backend/`;
- timeout `$NIRIKSHAN_VALIDATION_TIMEOUT_S` (default 3600 s); the process is killed on expiry and the run is marked `timeout`;
- output goes to a fresh `tempfile.mkdtemp(prefix="nirikshan-validate-")` directory (refused if it would sit next to the baseline); the directory is kept so the examiner can inspect it;
- the baseline file is hashed before and after; any change marks the run `failed`.

The comparison lists the parameters and versions that differ from the baseline (seed, trials, export, tool, ffmpeg, scenario subset), so `comparable` is true only for an identical configuration, plus `digest_match`, per-scenario metric differences and the re-run's own threshold violations (a run with export off reports the decode/hash thresholds as having no data). A row left `queued`/`running` by a process that has since exited is reported as `interrupted`.
